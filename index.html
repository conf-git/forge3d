Summary

TL;DR

  • Image-conditioned 3D generators often return a plausible object whose visible surface drifts from the input views. The views act only as a hint.
  • FORGE3D starts generation from the observation instead: depth seeds the sparse structure and image features seed the appearance latents, an idea we call latent forcing.
  • Forcing alone improves geometry without extra training, and fine-tuning with correspondence-aware multi-view attention improves appearance. These are claims of the paper; the ablation is not shown on this page.
  • FORGE3DBench provides cluttered, occluded, multi-view scenes with ground-truth meshes to test observation faithfulness.

Abstract draft placeholder

Recent 3D mesh generators produce visually compelling assets, yet faithfully reconstructing specific objects from real-world observations remains challenging. A practical mesh generation framework must jointly preserve observed 3D geometry and pixel-aligned appearance from one or more views while plausibly completing unseen regions. However, these observations often serve only as coarse conditioning signals, allowing generated geometry and appearance to deviate from the input. Moreover, existing 3D mesh benchmarks provide limited coverage of realistic scenes and challenging observation conditions needed to assess reconstruction faithfulness in real-world scenarios. To address these gaps, we introduce FORGE3D (Faithful Observation-Grounded 3D Mesh Generation), an observation-faithful mesh generation pipeline, and FORGE3DBench, a benchmark for evaluating observation faithfulness under realistic multi-view conditions. FORGE3D directly encodes geometric and visual observations into the generative latent space through geometry and appearance latent forcing, initializing generation from observed evidence. Applied to a pretrained generator, latent forcing already improves geometric fidelity without additional training, and fine-tuning with correspondence-aware multi-view attention further improves appearance. FORGE3DBench features more than 300 unique assets across 120 simulated scenes (20 in each of six capture configurations) with 24 camera viewpoints, encompassing varied object placements, lighting conditions, and occlusions. On the benchmarks shown on this page, FORGE3D is ahead of the four shown baselines at four views and mixed at one view; FORGE3D also uses observed depth that the baselines do not receive.

  • 01

    Latent forcing

    Observed geometry and appearance are encoded into the generator's latent space and used as the starting point of generation, so unseen regions are the only part left to the prior.

  • 02

    Correspondence-aware multi-view attention

    Each 3D voxel attends mostly to the image patches it projects into across views, so several views can be fused without changing the one-view behavior.

  • 03

    FORGE3DBench

    A photorealistic benchmark of multi-object scenes with calibrated views, metric depth, modal and amodal masks, and ground-truth meshes.

Plausible is not faithful

These baselines return a believable object whose visible surface still drifts from the input view. Left of the divider is the input, right is the baseline render from the same camera.

  • Every method reconstructs each object from the same input views (RGB and object masks) and the same cameras.
  • Alignment: the shown baselines (ReconViaGen, Amodal3R, Hunyuan3D-2mv, Cupid) produce meshes in their own object frame, so each is registered to the ground-truth frame by a dense rotation search followed by rigid ICP, with an input-view silhouette tie-break. Pixal3D is placed by camera only, since its output is pixel-aligned. FORGE3D is generated directly in the ground-truth frame and is not re-aligned.
  • Inputs differ in one respect: FORGE3D additionally uses the metric depth of the input views (oracle depth from the renderer, not predicted depth), while the baselines take RGB and masks only. FORGE3D is therefore grounded in the ground-truth frame through that depth; this is part of the method, not a like-for-like RGB-only comparison.

Method

Write the evidence into the generator

A two-stage latent generator normally starts each stage from noise. FORGE3D replaces that noise with the observation wherever a camera saw the object, and leaves only the unseen part to the generator. Pick a step to see where it acts.

Three objects per capture configuration were drawn with a fixed seed, then some were swapped within the same configuration to include cases where a method fails. This is a curated set, not an uncurated or exhaustive one. Failures of any method, ours included, are marked and kept.

  • Best baseline for an object is the baseline with the lowest Chamfer-L1 on that object.

What Robot table means. In robot-table scenes a robot arm with a gripper reaches into the scene and can grasp or occlude objects on the table, so an object may be partly hidden from some viewpoints. Ground and table scenes place objects on the floor or a table with no robot.

Methods are scored against the true mesh in its metric frame. FORGE3D uses the calibrated views and the observed depth; the baselines shown on this page use RGB and object masks only.
